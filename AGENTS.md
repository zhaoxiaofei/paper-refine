This repository MUST satisfy these constraints.

1. **Judgment is blind to provenance.** A judge sees the manuscript as an artifact, not as a product. It must not see which agent, arm, round, prompt, or prior session produced a version, and it must not see another session’s findings or discovery list. Identity in the panel is an opaque content token. External facts needed to score the paper — raw data, code, and admitted reviewer concerns — may appear only as anonymized evidence, never as a label of which candidate is which.

2. **The thing that was scored is the thing that wins.** A candidate’s identity is its content digest. The champion pin, the next round’s base, and the published package are that digest’s bytes, not a later “cleaned up” cousin. Content-identical candidates are one candidate. A version that was not judged cannot win. Tracking, redlines, PDF renders, and post-hoc relabeling of the ledger are not allowed to move a pin, a score, or an input manifest.

3. **Facts are not a revision surface.** The operator’s source, the pristine copy, raw data, and external review feedback are read-only. The manuscript is brought into agreement with them; they are never edited, dropped, or extended so that the manuscript looks right. They are not author prose, not a word-count surface, and not a scored improvement. When two sources disagree, the higher producer wins: code, then raw data, then figures, then tables, then main text, then supplementary text.

4. **No rule the venue did not state.** A venue is a recorded rule set. A journal name selects nothing. An article type is measured only against its own limits. If a limit, caption rule, section, or template requirement is absent, the pipeline counts and names the gap. It does not hard-code a journal, borrow another type’s numbers, copy exemplar prose, or let an agent invent a requirement. An invented rule is a defect in the pipeline, not a defect in the paper.

5. **There is one ranking function, and it is pure.** Every scored defect lands in the same six tiers — correctness, preservation, completeness, consistency, writing, formatting — and the same four severities. A newly noticed phenomenon is mapped into that scale; it does not become a seventh ranked class. Given the panel’s own ledger and the digests, the champion is a pure function: cumulative defect prefix, then median, mean, IQR, digest, and the incumbent stays on an exact statistic tie. Self-reported totals, conflict notes, and a defect audit may annotate that result. They may not replace its inputs.

6. **No role grades its own homework.** The session that writes a version does not score it. The session that audits scores does not select the champion. A repair of bookkeeping does not edit the manuscript. In a concern-scoped revision, changes stay inside the admitted concerns; an unscoped rewrite is a different mode, not a quiet upgrade of this one. The no-feedback path must stay the no-feedback path: adding a journal mode must not change what a root does when no journal mode is on.

7. **Output is not certification.** A `final_clean_version_<root name>/` always being written does not mean the decision passed. Certified means the panel was complete, the champion re-derives from the sheets, the evidence is unchanged, and the enabled gates are clean. A skipped integrity check is reported as skipped. Provisional and blocked results stay labeled and are never presented as a signed answer.

8. **Nothing that ships points at what does not ship.** A submitted document may refer only to content the submission itself carries. A path into an area or file the submission leaves out — the analysis code, the author’s own `README*.md`/`README*.txt` files, the raw data, the review feedback, the pipeline’s own bookkeeping and scratch — is a reference the reader can never resolve, so it is a defect in the submitted file, never a nuance of packaging. This does not flatten the areas into one kind: the raw data and the review feedback stay read-only inputs under rule 3, never revised and never submitted; the analysis code is revision content — revised and evaluated like any other file — and is submitted only when the operator asks for it; the author’s README files are carried by the corpus and never submitted. The rule binds one direction only — the submitted side is aligned with what actually ships, and an excluded area is never widened, edited, or extended so that a dangling reference appears to resolve.

9. **Every defect-seeking role has a non-zero probability of finding every real defect in the object it inspects — no rule may quietly set that probability to zero — and a defect that is found is classified and evidenced the same way whichever role found it.** For every role, a real defect inside the object it inspects is found by one run with a strictly positive probability, so infinitely many runs, on a package whose defects persist, find it at least once; and any run that finds it classifies it the same way. Detection is probabilistic; the mandate, the evidence and the classification are not:

   * the full defect-seeking passes — the probe and the round’s review — take the ENTIRE submission package as their object: every submitted document and file, every evidence area the operator assigned as input, the relationships between them, and the packaging itself. The other roles own the objects their design gives them — the audit the frozen review’s rows plus the states it must re-derive, the integration arm the candidates it merges and the frozen discovery list it must reconcile, the judge the comparison it received — and no rule, scan scope, prompt, or gate may narrow any role’s object to hide a class: no class of real defect — a class under the recorded rules, rule 4 — may be declared out of scope, exempt, or permanently unreviewable; a class a prompt does not name is not thereby excluded; and a class a reviewer would raise that no role’s mandate can reach is a defect in the PROMPTS, never a non-defect in the package;
   * no rule may make a defect invisible by construction: a scan that reaches only part of the package while instances of a class live outside its reach, a check whose reach is trimmed so the class falls out of it, or a filter that drops a class before any reviewer sees it is zero-probability coverage for that class, and therefore a pipeline defect. This forbids shrinking reach, never fixing precision: a check made accurate stops flagging non-defects without hiding any. Scoping a scan to its own legitimate surface — a formatting sweep over the submitted documents, a word count over author prose, never the read-only evidence areas (rule 3) — is not such a narrowing while the classes that apply to the skipped area stay covered by the passes that read it;
   * a categorical gap a run cannot close (a tool missing in this environment, a rendering the sandbox cannot open, a dataset the operator did not supply) is never a silent cap: it is recorded together with the classes it leaves unexamined, so the next run samples them again. A gap that is stated keeps its probability; a gap that is hidden sets it to zero;
   * independence and variation are what make the probability accumulate: the finding-deriving passes — the round’s review, the probe, and the judge’s own discovery pass — read their object cold, without another session’s findings or discovery list (rule 1’s blinding, applied to defect-seeking as well as to judges), and successive sessions are expected to vary their entry points, orderings and enumerations rather than repeat one route. A role that adjudicates or acts on another session’s rows (the audit; the revision and integration arms) receives them as rows to dispose of, fix or reconcile, never as a substitute for examining what its own mandate covers. Sampling breadth is a correctness requirement, never a stylistic preference;
   * what is FOUND travels: its tier and severity are the same whichever role found it (rule 5’s scale), and its evidence is re-runnable by a different session — a location, a verbatim quote, or a computation another role can repeat; any one of the three is enough. A finding no other role can verify is not yet a finding;
   * deterministic agreement between roles is required of the scale and the evidence, NEVER of a single session’s detection list — detection lists may differ between sessions, and that variation is the sampling the probability rests on. Two asymmetries keep this consistent with the roles’ design: the auditor’s agreement is a DISPOSITION — uphold a row, or drop it with evidence — so a drop is a legitimate outcome, not a disagreement to be suppressed; and a judge’s object is the comparison it received, so a defect outside that comparison is out of its object rather than missed. Silence from a role whose object did not contain the defect is neither agreement nor contradiction;
   * the guarantee stays probabilistic: a session that runs, examines and reports nothing has not proven the package clean, and no output may present a completed review — probe, review, audit or panel — as an exhaustiveness proof. Only the stronger claim, that a class has probability zero, is forbidden outright.

10. **On a contradiction, the earlier text wins.** If two rules contradict each other, the rule that appears first in this file — the lower number — prevails, and the later rule is read as narrowed to what the earlier one allows. If two sentences contradict each other — in one rule or in two — the sentence that appears first prevails, and the later sentence is read as narrowed to what the earlier one allows. A contradiction remains a defect in this file, to be repaired by editing; precedence is the default reading until the repair is made.
