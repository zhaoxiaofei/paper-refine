This repository MUST satisfy these rules (i.e., constraints). These rules are binding on every code, command, stage, prompt, test and documentation change. A violation of any rule is a bug, not an acceptable trade-off; a change that needs an exception must amend this file first.

Rule 1. **Every session is exactly one role, and its role is the whole of its mandate.** A session reads the inputs its role is given, writes the one product its role owns, and neither performs another role’s work nor scores or ranks a product it wrote (rule 7):

   * REWRITE (when the round stages rewrites) — produces a complete alternative version of the base with the same documents, claims, data, and conclusions, reorganized and rewritten; it is not the reviewer, builds no finding ledger, edits no input, and its candidate is judged like any other;
   * REVIEW (round phase 1) — runs the adopted sweeps and judgment passes (M1–M36, J1–J5) and the discovery round (D0–D5) over the round’s base, and writes its F-* and X-* rows into the round’s frozen finding list (the orchestrator appends the probe’s X-9xx rows after the probe’s cold pass and before the audit): identification only, nothing edited, nothing scored;
   * PROBE — reads the same corpus cold and unanchored (no checklist, no finding list, no review artifact) and files any defensible defect class as X-9xx: identification only; its X-9xx rows join the reviewer’s in the frozen list for the auditor’s disposition, and its independence from the checklist is the point;
   * AUDIT — disposes every frozen finding (confirm, or drop with evidence; silence is not allowed) and attacks boilerplate closures and coverage gaps; it GENERATES NO NEW FINDINGS (no AU-* rows). Its product is the audit report: one disposition per frozen finding with the evidence that decides it. The same audit record carries an unresolved-observations section (`audit/UNRESOLVED.md`) for a defect it notices outside the frozen list — one line per observation, with its location and re-runnable evidence, addressed to the next review, which alone may file it on the shared scale (rule 6); an observation is not a finding, it never enters the frozen list the revisers act on, and no reviser acts on it. It edits no manuscript, review, or package, and its report is what the revisers act on. `--audit off` / `--no-audit` skips it: the frozen findings then reach the revisers unaudited.
   * REVISE (round phase 2) — applies the audited (or, when the review audit is skipped, the frozen) findings to the round’s base and writes its revised package (in a concern-scoped mode, inside the admitted concerns) plus its own change and manual report. Before applying each finding it RE-VALIDATES that finding against the base and the source hierarchy and records the verdict (`confirmed` / `rejected`, with the reason) in its ledger; a rejected finding is carried as `unable — <reason>` and is not edited. It does not score or select, and the review and pristine copies it reads stay byte-identical;
   * REVISION AUDIT (after each revise arm, before integration/judge/round decision) — audits that arm’s revised version for the revision’s own classes and writes that arm’s BOUNDED-REPAIR PLAN (data): one row per defect it confirms in that revision, with the location, the wrong text or value, the correct value and the basis a different session can re-run, and the exact proposed repair. It GENERATES NO REVISED FILE and edits nothing (no manuscript, package, ledger or manual report); it does not re-review the submission and runs no discovery hunt over it. It does not score, rank or select (rule 7). `--revision-audit off` skips it: that arm’s revised version is then final;
   * BOUNDED REPAIR (only when that arm’s revision-audit plan is non-empty) — a REVISE-class session that applies the plan to that arm’s revised package and writes that arm’s FINAL REVISED VERSION. It RE-VALIDATES every planned repair against the revised package, the base and the source hierarchy before applying it (recording `confirmed` / `rejected` per row), applies only the confirmed rows, updates its ledger/CHANGELOG/MANUAL_STEPS and reports, and never re-reviews or re-audits. ONE pass only: a defect the post-repair verification still finds is recorded for the round’s decision, not repaired in a loop. When the revision audit is skipped or the plan is empty, this role does not run and that arm’s revised version is final;
   * INTEGRATE (when the round’s mask stages runs) — one run per pool member reworks its own copy with every other member as donor, ports a fix only where the source hierarchy and the frozen discovery list allow it, and reconciles every frozen X-* id in its difference ledger; it authors no discovery hunt and judges nothing;
   * JUDGE — scores the anonymized comparison it received, never a finding list and never provenance (rule 4); it re-derives its own bounded discovery pass over every side and files its rows on the shared scale (rule 6), and the champion stays a pure function of the sheets and the digests (rule 6);
   * JOURNAL-MODE SESSIONS — the feedback and concerns sessions turn the human and pre-filtered LLM feedback into the complete enumerated concern ledger (and, where the mode replaces the general review, the finding list the single revision session follows); the response session writes the point-by-point response-to-reviewers letter — every concern id exactly once, quotes verbatim, only shipped targets cited; none of these edits a manuscript;
   * SCOPED REPAIR (after a rejected postcheck) — repairs only the rejected bookkeeping of a stage that already finished: it never creates a deliverable, never fabricates a missing record, and never touches the manuscript, the corpus, a package, or another stage’s deliverables.

The session order for a general round is REVIEW and PROBE (in parallel, when the probe is enabled) → AUDIT (optional) → REVISE (each arm) → REVISION AUDIT (per revise arm, optional) → BOUNDED REPAIR (per revise arm, only when that arm’s plan is non-empty) → each revise arm’s final revised version → INTEGRATE (when staged) → JUDGE → the round decision. The two auditors are optional by configuration (`--audit off` / `--no-audit` and `--revision-audit off`); when one is skipped its data is absent and the next step runs on unaudited input — the reviser on the frozen findings, that arm’s revised version as final — and the skip is recorded.

Where a session sees something outside its mandate, it records it for the role that owns it and never does that role’s work itself. The orchestrator is not a session role: it schedules these sessions, verifies their products, and computes the champion (rule 6).

Rule 2. **Facts are not a revision surface.** The operator’s source, the pristine copy, raw data, and external review feedback are read-only. The analysis code is not one of them — rule 9 makes it revision content. The manuscript is brought into agreement with them; they are never edited, dropped, or extended so that the manuscript looks right. They are never treated as the submission’s prose, never a word-count surface, and never a scored improvement. When two sources disagree, the higher producer wins: code, then raw data, then figures, then tables, then main text, then supplementary text.

Rule 3. **No rule the venue did not state.** A venue is a recorded rule set. A journal name selects nothing. An article type is measured only against its own limits. If a limit, caption rule, section, or template requirement is absent, the pipeline counts and names the gap. It does not hard-code a journal, borrow another type’s numbers, copy exemplar prose, or let an agent invent a requirement. An invented rule is a defect in the pipeline, not a defect in the paper.

Rule 4. **Judgment is blind to provenance.** A judge sees the manuscript as an artifact, not as a product. It must not see which agent, arm, round, prompt, or prior session produced a version, and it must not see another session’s findings or discovery list. The panel refers to a version only by an opaque content token. External material needed to score the paper — raw data, code, and admitted reviewer concerns — may appear only as anonymized evidence, never as a label of which candidate is which.

Rule 5. **The thing that was scored is the thing that wins.** A candidate’s identity is its content digest. The champion pin, the next round’s base, and the published package are that digest’s bytes, not a later “cleaned up” cousin. Content-identical candidates are one candidate. A version that was not judged cannot win. Tracking, redlines, PDF renders, and post-hoc relabeling of the ledger are not allowed to move a pin, a score, or an input manifest.

Rule 6. **There is one ranking function, and it is pure.** Every scored defect lands in the same six tiers — correctness, preservation, completeness, consistency, writing, formatting — and the same four severities. A newly noticed phenomenon is mapped into that scale; it does not become a seventh ranked class. Given the panel’s own ledger and the digests, the champion is a pure function: cumulative defect prefix, then median, mean, IQR, then digest; an exact (median, mean, IQR) tie keeps the incumbent, and that retention overrides the prefix. Self-reported totals, conflict notes, and a defect audit may annotate that result. They may not replace its inputs.

Rule 7. **No role grades its own homework.** The session that writes a version does not score it. The session that audits scores does not select the champion. The revision audit neither edits nor selects; the bounded repair is a revision role and never selects. A candidate changed by the bounded repair is a new artifact: it is re-verified and re-judged before it can win. A repair of bookkeeping does not edit the manuscript. In a concern-scoped revision, changes stay inside the admitted concerns; an unscoped rewrite is a different mode, not a quiet upgrade of this one. The no-feedback path must stay the no-feedback path: adding a journal mode must not change what a root does when no journal mode is on.

Rule 8. **Every defect-seeking role has a non-zero probability of finding every real defect in the object it inspects — no rule may quietly set that probability to zero — and a defect that is found is classified and evidenced the same way whichever role found it.** For every defect-seeking role, a real defect inside the object it inspects is found by one run with a strictly positive probability, so infinitely many runs, on a package whose defects persist, find it at least once; and any run that finds it classifies it the same way. Detection is probabilistic; the mandate, the evidence, and the classification are not:

   * the full defect-seeking passes — the probe (when enabled) and the round’s review — take the ENTIRE submission package as their object: every submitted document and file, every evidence area the operator assigned as input, the relationships between them, and the packaging itself. The other roles own the objects their design gives them — the audit the frozen findings (the review’s rows and, when the probe ran, the probe’s) plus the states it must re-derive, the integration arm the candidates it merges and the frozen discovery list it must reconcile, the revision audit the revision’s own classes (read against the base, the revised package, the findings the revisers used — audited, or frozen when the review audit was skipped — and the revision ledger; not a re-review of the submission), the bounded repair the bounded-repair plan and the revised package it edits, the judge the comparison it received — and no rule, scan scope, prompt, or gate may narrow any role’s object to hide a class: no class of real defect — a class under the recorded rules, rule 3 — may be declared out of scope, exempt, or permanently unreviewable; a class a prompt does not name is not thereby excluded; and a class a reviewer would raise that no role’s mandate can reach is a defect in the PROMPTS, never a non-defect in the package;
   * no rule may make a defect invisible by construction: a scan that reaches only part of the package while instances of a class live outside its reach, a check whose reach is trimmed so the class falls out of it, or a filter that drops a class before any reviewer sees it is zero-probability coverage for that class, and therefore a pipeline defect. This forbids shrinking reach, never fixing precision: a check made accurate stops flagging non-defects without hiding any. Scoping a scan to its own legitimate surface — a formatting sweep over the submitted documents, a word count over the submission’s own prose, never the read-only evidence areas (rule 2) — is not such a narrowing while the classes that apply to the skipped area stay covered by the passes that read it;
   * a categorical gap a run cannot close (a tool missing in this environment, a rendering the sandbox cannot open, a dataset the operator did not supply) is never a silent cap: it is recorded together with the classes it leaves unexamined, so the next run samples them again. A gap that is stated keeps its probability; a gap that is hidden sets it to zero;
   * independence and variation are what make the probability accumulate: the finding-deriving passes — the round’s review, the probe, and the judge’s own discovery pass — read their object cold, without another session’s findings or discovery list (rule 4’s blinding, applied to these passes as well as to the panel), and successive sessions are expected to vary their entry points, orderings, and enumerations rather than repeat one route. A role that adjudicates or acts on another session’s rows (the audit; the revision and integration arms) receives them as rows to dispose of, fix, or reconcile, never as a substitute for examining what its own mandate covers. Sampling breadth is a correctness requirement, never a stylistic preference;
   * what is FOUND travels: its tier and severity are the same whichever role found it (rule 6’s scale), and its evidence is re-runnable by a different session — a location, a verbatim quote, or a computation another role can repeat; any one of the three is enough. A finding no other role can verify is not yet a finding;
   * deterministic agreement between roles is required of the scale and the evidence, NEVER of a single session’s detection list — detection lists may differ between sessions, and that variation is the sampling the probability rests on. Two asymmetries keep this consistent with the roles’ design: the auditor’s agreement is a DISPOSITION — uphold a row, or drop it with evidence — so a drop is a legitimate outcome, not a disagreement to be suppressed; and a judge’s object is the comparison it received, so a defect outside that comparison is out of its object rather than missed. Silence from a role whose object did not contain the defect is neither agreement nor contradiction;
   * the guarantee stays probabilistic: a session that runs, examines, and reports nothing has not proven the package clean, and no output may present a completed review — probe, review, audit or panel — as an exhaustiveness proof. Only the stronger claim, that a class has probability zero, is forbidden outright.

Rule 9. **Nothing that ships points at what does not ship.** A submitted document may refer only to content the submission itself carries. A path into an area or file the submission leaves out — the analysis code when it does not ship, the author’s own `README*.md`/`README*.txt` files, the raw data, the review feedback, the pipeline’s own bookkeeping and scratch — is a reference the reader can never resolve, so it is a defect in the submitted file, never a nuance of packaging. This does not flatten the areas into one kind: the raw data and the review feedback stay read-only inputs under rule 2, never revised and never submitted; the analysis code is revision content — revised and evaluated like any other file — and is submitted only when the operator asks for it; the author’s README files are carried by the corpus and never submitted. The rule binds one direction only — the submitted side is aligned with what actually ships, and an excluded area is never widened, edited, or extended so that a dangling reference appears to resolve.

Rule 10. **Output is not certification.** That a `final_clean_version_<root name>/` is always written does not mean the decision passed. Certified means the panel was complete, the champion re-derives from the sheets, the evidence is unchanged, and the enabled gates are clean. A skipped integrity check is reported as skipped. Provisional and blocked results stay labeled and are never presented as a signed answer.

Rule 11. **A root runs a frozen copy, never the maintained checkout.** `setup` must copy every file the running project executes or reads by path into the `--root` tree before the root is used. This includes, but is not limited to: the driver(s), their ordered parts, companion modules and adapters (the formatter and its parts, redline and Qwen adapters), venue profiles, schemas, prompt/config assets and any other file whose content can change a stage's behavior. The copy must be self-contained: after `setup`, modifying, updating, moving or deleting files in the maintained checkout must not change what that root executes, reads, validates, prompts with or scores with. Reading a repository file from a root at run time instead of using the root's frozen copy is a bug; add the asset to the setup copy and the module/asset manifest. A feature that adds a runtime file without freezing it into new roots violates this rule.

Last rule. **On a contradiction, the earlier text wins.** If two rules contradict each other, the rule that appears first in this file — the lower number — prevails, and the later rule is read as narrowed to what the earlier one allows. If two sentences contradict each other — in one rule or in two — the sentence that appears first prevails, and the later sentence is read as narrowed to what the earlier one allows. A contradiction remains a defect in this file, to be repaired by editing; precedence is the default reading until the repair is made.
